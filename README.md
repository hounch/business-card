# Digital Business Card
Backend-приложение для цифровой визитки, разработанное в рамках тестового задания. 
API предоставляет данные проифля, навыков, опыта работы и проектов через GraphQL (Apollo Sandbox).

## Технологический стэк
- **Node.js** (v22+) + **TypeScript**
- **NestJS** (Code-first подход для GraphQL)
- **GraphQL** (Apollo Server)
- **Prisma ORM** (PostgreSQL)
- **Docker** + **Docker Compose**

## Архитектурные решения 

### 1. Модульная структура NestJS
- Приложение разделено на доменные модули (`ProfileModule`, `PrismaModule`).
- **Слой Resolvers** (`profile.resolver.ts`) отвечает только за приём GraphQL-запросов и не содержит бизнес-логики.
- **Слой Services** (`profile.service.ts`) содержит бизнес-логику и работает с базой данных.
- **PrismaService** инкапсулирует подключение к БД и является единственной точкой доступа к данным.

### 2. Работа с GraphQL и оптимизация запросов
Выбран подход **Code-first** (схема генерируется из TypeScript-декораторов). 
Для оптимизации работы с вложенными данными (профиль и его связи: навыки, опыт, проекты) используется механизм `include` в Prisma. Это позволяет избежать проблемы **N+1** (когда на один запрос профиля делается N дополнительных запросов за его навыками) на уровне базы данных, выполняя один эффективный SQL-запрос с `JOIN`.

### 3. База данных и Prisma
В качестве СУБД выбран **PostgreSQL**.
- Схема данных описана в `prisma/schema.prisma`.
- Связи настроены через внешние ключи с каскадным удалением (`onDelete: Cascade`), чтобы при удалении профиля не оставалось лишних данных.
- Для автоматического заполнения базы используется скрипт `prisma/seed.ts`. Он идемпотентен (перед вставкой очищает таблицы), что позволяет запускать его многократно без создания дублей.

### 4. Docker и автоматизация
- Для запуска приложения достаточно одной команды: `docker compose up --build -d`, 
- В `docker-compose.yml` настроены два сервиса: `db` (PostgreSQL) и `app` (NestJS).
- Настроен `healthcheck` для базы данных. Приложение (`app`) ждёт полной готовности БД, прежде чем начать запуск.
- В `Dockerfile` настроен многоэтапный процесс: при старте контейнера автоматически применяются миграции (`prisma migrate deploy`) и запускается сид (`prisma db seed`), после чего стартует сам сервер. Это полностью закрывает требование ТЗ "при запуске приложения база данных должна быть автоматически подготовлена и заполнена".

## Как запустить локально (через Docker)
1. Убедитесь, что установлены **Docker** и **Docker Compose**.
2. Клонируйте репозиторий.
3. Выполните команду:
```bash
docker compose up --build -d
```
4. Откройте http://localhost:3000/graphql для работы с Apollo Sandbox.

## Пример GraphQL-запроса
```graphql
query {
    profile {
        name
        description
        skills {
            name
        }
        experience {
            company
            position
        }
        projects {
            name
        }
    }
}
```
